# درس ۰۰ — نقشه و معماری پروژه

## هدف درس

قبل از اجرای برنامه باید بدانیم هر قسمت چه مسئولیتی دارد. ساختار پروژه عمداً ماژولار است تا هر بخش مستقل توسعه و آزمایش شود.

## نقشه پوشه‌ها

- `core/`: توابع Python و منطق محاسباتی.
- `databases/`: داده‌های JSON شامل ابعاد لوله و مشخصات مواد.
- `tests/`: آزمون‌های خودکار برای کنترل رفتار توابع.
- `sources/`: ثبت منابع استانداردی و علمی داده‌ها.
- `docs/tutorial/`: همین مجموعه درس‌های آموزشی.
- `main.py`: نقطه ورود برنامه و منوی متنی کاربر.
- `requirements.txt`: وابستگی‌های خارجی Python.

## جریان اجرای برنامه

وقتی کاربر `python main.py` را اجرا می‌کند، تابع `main()` منو را نمایش می‌دهد. انتخاب کاربر به تابع مناسب هدایت می‌شود. برای مثال، انتخاب ابعاد لوله، تابعی از `core/pipe_database.py` را فراخوانی می‌کند. آن ماژول داده را از JSON می‌خواند و نتیجه را به main برمی‌گرداند.

بنابراین main محل نگهداری جدول ابعاد یا فرمول‌های علمی نیست؛ فقط ورودی و خروجی کاربر را مدیریت می‌کند.

## چرا این جداسازی مهم است؟

- می‌توانیم منوی متنی را بعداً با رابط گرافیکی جایگزین کنیم.
- توابع اصلی بدون اجرای منو قابل استفاده‌اند.
- تست هر ماژول مستقل می‌ماند.
- خطای رابط کاربری با منطق مهندسی مخلوط نمی‌شود.
